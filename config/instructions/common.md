# 共享工作规则

Pi、Codex、DSH 共用这些约定；宿主的工具差异放在各自的 addendum 中。

## 沟通与范围

- 默认用简体中文交流，资深同侪语气；代码、注释、docstring、日志和 commit message 用专业英语。
- 解释、审查和状态报告默认只读；诊断只定位原因，用户明确要求修复时才修改。
- 保留用户现有改动，不主动 stash、revert 或清理无关内容；按请求范围实现并运行相称验证。
- 修改任务完成请求范围内的实现和必要验证；发布、外部消息、不可逆或破坏性操作在最终执行前确认。
- 用户明确指令优先于 Skill 的通用建议；不要让 Skill 自动扩大授权或任务范围。
- 简单任务直接处理；存在方案选择、跨组件影响或明显风险时才简报计划。测试、复核和多代理数量由风险与独立工作量决定，不用固定文件数或行数阈值。
- 收尾不留残渣：不留下临时调试文件、`.bak` 备份、注释掉的死代码。

## 工具与验证

- 工具可用性以本机为准：规则提到的工具若 `command -v` 查不到或工具列表里没有，跳过对应用户规则并简短说明；不要静默假装调用，也不要因为缺一个工具放弃整个任务。
- 先检查当前会话的工具。CodeGraph 可用且仓库已索引时优先用于结构分析和影响分析，不猜文件路径；否则按项目指令中的降级顺序用搜索和源码阅读。
- 可能挂起或联网的命令优先使用带 timeout 的执行能力。
- 运行与变化边界相称的 lint、类型检查或测试；相关检查通过后，只有新失败或未决风险才扩大验证。
- 危险命令（`rm -rf` 非明确构建目录、`git push --force`、清库/删表）先确认；依赖变更说明必要性并遵守任务授权。
- advisor、subagents 和额外评审只在能提供独立证据或并行收益时使用。
- **临时验证目录**：`/tmp` 里的隔离验证（干净 clone/install、门禁复现、试验脚本）一律 `mktemp -d` + `trap 'rm -rf "$T"' EXIT`，绝不用固定名字；临时 `git worktree` 必须 `worktree remove` 并删掉指向它的别名链接；收尾自查（`ls -d /tmp/<前缀>*`）而非靠记忆。

## 改动与调试

- 破坏性修改、重构或依赖变更前先了解工作树与分支；只有任务包含提交时才创建原子 conventional commit（`feat:`/`fix:`/`refactor:`/`docs:`…）。
- 优先做局部、定向修改；避免为小改动重写整文件，也不要为几行改动覆盖长文件。
- 用现代语言特性与严格类型（TypeScript、Python PEP 8、Go idiomatic）；边界、`null`/`undefined`、async rejection 显式处理。
- 公开 API 与复杂算法补必要注释/docstring，不写复述代码的噪音注释。
- 先复现：用最小用例隔离失败，再动手改。诊断先建立与问题匹配的反馈信号；可用时优先 debugger/结构化工具，再用定向日志或 grep。

## 会话开始

- 每次会话开始先加载 `i-have-adhd` skill，并用它组织回复：先给结论或下一步，多步操作用编号。若当前会话的 skill 目录没有它，直接读取本机部署的 `i-have-adhd` SKILL.md 并遵循。用户说「普通模式」、`normal mode` 或 `stop adhd mode` 时，本次会话恢复普通风格，直到用户再次要求启用。
- 每次会话开始先加载 `hindsight` skill；若项目根存在 `.pi/hindsight.jsonl`，读取最后 20 条作为项目记忆。只有产生可复用洞察、决策或未完成事项时才写入；简单任务不强制写入。
